## שלב 0 — הקמת הפרויקט
**מטרה:** שלד שעובד מקצה לקצה, לפני שיש בו לוגיקה.

**Git ו־monorepo**
- ‏`git init`, קובץ `.gitignore`, ו־repo **פרטי** ב־GitHub (נדרש ל־Actions).
- Monorepo עם npm workspaces:
  - `packages/engine`: TypeScript טהור, עם Jest.
  - `packages/protocol`: הממשק וטיפוסי ההודעות.
  - `apps/mobile`: ‏Expo SDK 57, ‏expo-router, ‏TypeScript, ‏Zustand.
  - `apps/server`: ‏Node, ‏TypeScript, ‏Colyseus.
- **חבילות משותפות:** ב־`package.json` של כל חבילה, `main` ו־`types` מצביעים על `src/index.ts`.
  - בשרת: `tsx` בפיתוח, ו־`tsc -b` עם project references ל־build.
  - ב־Metro: ‏SDK 57 מזהה monorepo לבד, אז לא דורסים את `watchFolders`.
  - לוודא שיש עותק יחיד של react ושל react-native: הפקודה `npm ls react react-native` צריכה להחזיר גרסה אחת של כל אחת.
- **כלים:** סקריפטים שעובדים גם ב־Windows (`cross-env`). ‏ESLint ו־Prettier משותפים.
  ב־engine יש כלל ESLint שאוסר `Math.random()` ו־`Date.now()`. השעון וה־RNG מוזרקים.
- **סקריפטים בשורש:** `npm test`, ‏`npm run mobile`, ‏`npm run server`.

**האפליקציה**
- **Development Build, לא Expo Go**, כי Firebase דורש קוד נייטיב.
  - `expo-dev-client`, וקובץ `eas.json` עם הפרופילים development, ‏preview ו־production.

- **ספריות נייטיב, כבר עכשיו, עם `npx expo install`:** react-native-reanimated, ‏react-native-worklets, ‏react-native-gesture-handler, ‏@shopify/react-native-skia,

## שלב 1 — מנוע סודוקו (`packages/engine/sudoku`)
**מטרה:** כל הלוגיקה של הסודוקו עצמו, עם בדיקות.

**לוח ופתרון**
- כלים ללוח: אינדקסים, שמות משבצות (D5), שכנים, יחידות (שורה, עמודה, ריבוע), אפשרויות למשבצת.
- פותר מהיר, ובדיקה שלפתרון יש פתרון יחיד.
- **פותר לוגי** עם הטכניקות: בודד גלוי, בודד נסתר (בשורה, בעמודה ובריבוע), צמצום ריבוע־שורה, זוג גלוי וזוג נסתר.
  כשהפותר הלוגי נתקע, הלוח מסווג `beyond`, ולא נכנס לאף סוג משחק.
- **דירוג קושי** לפי הטכניקות הנדרשות: מהיר, רגיל או קשה (אפיון 5.2 ו־20).

**הסברים (אפיון 13.2)**
- `explain(board, cell)` מחזירה מבנה נתונים.
- כשאין טכניקה אחת שקובעת את המשבצת, היא מחזירה `{ technique: 'chain', steps[] }`.
- `formatExplanation(expl, 'he' | 'en')`. בעברית, שמות משבצות ונוסחאות עטופים בתווי בידוד כיוון (LRI…PDI), כדי שלא יתהפכו.

**ניקוד**
- **ניקוד** (אפיון 6.4): `moveScore(board, cell, digit)`, שמחזירה `{row, col, box, num, X, Y, points}`.
- **קנס** (6.5): `missedPoints(board, cell, rightDigit)`, הנקודות שהספרה הנכונה הייתה מקבלת. אין לזה הגדרה ב־`rules`, ואין חלופה (החלטה של משה, 15.10.2026).
- **עלות הפרעה** (7.2): `interferenceCost(n)`.

**מאגר לוחות (אפיון 20)**
- **ייבוא:** קורא את `assets/puzzles/sudoku-bank-690.csv` ושומר את `packages/engine/data/puzzles.json`.
  - כל רשומה: `{id, givens, solution, gameType, techniques[], givensCount, source, pool}`.
  - `id` הוא hash יציב של הרמזים. לוחות לא תקינים נכנסים לדוח ולא נשמרים.
- **מחולל לוחות:** `npm run puzzles:generate -- --type hard --count 300`. יוצר לוח עם פתרון יחיד, מדרג אותו, ושומר אותו רק אם הוא מתאים לסוג.
- **נוסף ב־15.10.2026 [D43]:** מספר הספרות הגלויות בפתיחה לפי סוג: מהיר 45–50, רגיל 35–40, וקשה כמו שהיה. `npm run puzzles:givens` מביא את המאגר לטווחים, והייבוא והמחולל מוציאים לוחות שכבר בטווח (אפיון 5.2, 20).
- **בחירת לוח בלי חזרה** (אפיון 20), כולל איפוס כשהשחקן שיחק ב־80% מהמאגר.

**סיום:**
- בדיקה שמוודאת את דוגמת הניקוד באפיון 6.4 (`X = 7, Y = 6 → 3.5`).
- **הדוח על המאגר הקיים מראה 690 מהיר, 0 רגיל ו־0 קשה.** אחרי המחולל: לפחות 200 לוחות לכל סוג.
- ההסבר בעברית לבודד גלוי נראה כמו הדוגמה באפיון 13.2 (`D5 → 7`), ובדיקת snapshot מוודאת את זה.
- בדיקה של לוח קשה שבו ההסבר הוא שרשרת של 2 צעדים לפחות.

## שלב 2 — מנוע חוקי המשחק (`packages/engine/game`)
**מטרה:** מכונת המצבים של משחק שלם, שרצה גם בשרת וגם במכשיר.

**ממשק ומכונת מצבים**
- **ב־`packages/protocol`:** הממשק `GameHost`, עם `select`, ‏`release`, ‏`place`, ‏`interfere`, ‏`react`, ‏`surrender` ו־`subscribe(onEvent)`, וטיפוסי ההודעות והאירועים מאפיון 18.
- `createGame(config, { clock, rng })`. השעון וה־RNG מוזרקים.
- `applyAction(state, action)` מחזירה `{ state, events }`, כאשר `state` הוא אובייקט חדש (immutable).
- `tick(state, now)` מטפלת בטיימרים.

**החוקים**
- **נעילות:** זמני חשיבה, שחרור, ושנייה של המתנה לפני נעילה חוזרת, אחרי כל שחרור (6.2).
- **עצירת טיימרים:** בזמן הפרעה ובזמן הקפאה (6.2, סעיף קטן 7).
- **מהלכים:** מהלך נכון ומהלך שגוי (6.4, 6.5). השבתת ספרות שכבר נוסו (6.3).
- **הפרעות:** עלות, מצב שבו אין מספיק נקודות, ואין הפרעה כפולה (7.2).
- **תגובות:** עם הגבלת קצב (8).
- **סיום:** כניעה, סיום משחק, מיקום ותיקו (6.6, 6.7).
- **ניתוק:** Grace, הקפאה במשחק של 2 שחקנים, ונטישה (16.2).
- **מודל התור:** `rules.turnModel`, במקביל או בתורות (D1).

**מעבר לחוקים**
- יומן אירועים.
- `toView(state, playerId)`: התצוגה של השחקן, **בלי הפתרון**.
- `replay(events)`: שחזור המצבים מתוך היומן.
- **`LocalGameHost`** מממש את `GameHost` במכשיר. בשלב 7, ‏`RemoteGameHost` יממש את אותו ממשק בלי שינוי במסכים.
