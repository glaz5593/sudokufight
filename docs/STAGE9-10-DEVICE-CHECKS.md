# שלבים 9–10: בדיקות במכשירים (למשה)

הבדיקות שמשלימות את תנאי ה"סיום" של שלבים 9 ו־10 (`docs/02-WORK-PLAN.md`), ושאי אפשר להריץ ב־Jest: שני חשבונות בשני טלפונים, ומשחק של 4 עם שני טלפונים ושני `fake-client`.

מה שכבר נבדק אוטומטית, בלי טלפון:

- **`apps/mobile/src/__tests__/ranked.e2e.test.tsx`:** כל המסלול במסכים האמיתיים של האפליקציה, מול שרת מזויף.
  - בית ← "שחק" ← "מדורג · 2" ← סוג משחק ← חיפוש (הטווח מתרחב) ← נמצא יריב ← 3-2-1-GO ← משחק עד הסוף ← תוצאות (הדירוג סופר מהישן לחדש) ← הדירוג החדש בבית ← המשחק בהיסטוריה תחת "מדורג".
  - גם Match-Timeout ("המשך לחפש" ו"שחק מול בוט בינתיים"), מצב בלי אינטרנט, ומשחק מדורג של 4 עד הפודיום.
- **`apps/server/test/appMatchmaking.contract.test.ts`:** הקוד של האפליקציה מול השרת האמיתי. שני חשבונות מוצאים זה את זה, משחקים, והדירוג השמור שווה לנוסחה.
- **`apps/server/test/ranked.e2e.test.ts`:** הטווח מתרחב כל 5 שניות, ומי שמחפש לבד מקבל `nextRange: null` ("אין שחקנים אחרים"). יריבים חדשים מקבלים עדיפות, Match-Timeout אחרי 60 שניות, ובאפשרות A מתעדכן `normal-2p`.
- **`apps/server/test/fourPlayers.e2e.test.ts`:** משחק של 4 לקוחות `fake-client` עם מיקום מלא ודירוג לפי Elo ל־4. רץ ב־CI.

> **בקצרה: `npm run dev:lan -- --write-env`** מהשורש (`--seed` מוסיף נתוני דוגמה לאתר הניהול), ואז `npm run mobile -- --clear` בחלון שני.
> הפקודה עושה את סעיפים 1, 3 ו־4 כאן: טוענת את המאגר המדורג אם חסר, מפעילה את השרת, וכותבת את כתובת המחשב ב־Wi-Fi ל־`apps/mobile/.env.local`.
> אחר כך היא מדפיסה את הכתובת לבדיקה מהטלפון (`/health`), את אתר הניהול והסיסמה, פקודות ל־Windows Firewall, ואת פקודות ה־`fake-client` למשחק של 4.
> את סעיף 2 (`npm run admin:build`) עדיין מריצים פעם אחת לבד. הפירוט ב־README, בסעיף "טלפונים ב־Wi-Fi".

## הכנה (פעם אחת)

1. **מאגר הלוחות המדורגים:** כשהשרת **עצור**, מהשורש: `npm run db:seed-puzzles`. בלי זה משחק מדורג לא מתחיל.
2. **אתר הניהול (בשביל בדיקת הדירוג):** `npm run admin:build`, פעם אחת, לפני שמפעילים את השרת.
3. **השרת:** `npm run server`. הוא רץ בפורט 2567 במצב פיתוח, ומקבל את חשבונות הפיתוח של האפליקציה.
4. **כתובת השרת בטלפונים:** מעתיקים את `apps/mobile/.env.example` ל־`apps/mobile/.env.local`, ומשנים ל־`EXPO_PUBLIC_SERVER_HOST=<כתובת ה־IP של המחשב ברשת>`, למשל `192.168.1.20`.
   - שני הטלפונים והמחשב על אותה רשת Wi-Fi.
   - את כתובת ה־IP מוצאים ב־PowerShell עם `ipconfig`, בשורה IPv4 של ה־Wi-Fi (או ש־`npm run dev:lan` מדפיס אותה).
5. **Metro:** מתוך `apps/mobile` מריצים `npx expo start --clear`. ה־`--clear` חשוב אחרי כל שינוי ב־`.env.local`, כי הכתובת נכנסת לקוד בזמן הבנייה של ה־bundle.
   - **Development Build:** שלבים 9–10 לא הוסיפו מודול native. אם ה־build שבטלפונים נבנה אחרי שלב 8, אין צורך בבנייה חדשה. אם הוא מלפני שלב 8, בונים מחדש לפי ה־README.
   - כדי לוודא את הכתובת: בבית, בשורה "פיתוח" בתחתית ← "משחק מקוון". כתובת השרת מופיעה שם.
6. **שני חשבונות:** בכל טלפון נרשמים עם שם אחר ומייל אחר.
   - **בלי קובצי Firebase** (מצב פיתוח, התג "מצב פיתוח" במסכי החשבון): לא נשלח מייל. בבית לוחצים על הבאנר "המייל שלך עוד לא מאומת" ← "אימתתי".
   - **עם Firebase:** פותחים את קישור האימות מהמייל, ואז "אימתתי". השרת צריך את `FIREBASE_PROJECT_ID` ב־`apps/server/.env`.
   - **בלי מייל מאומת אין משחק מדורג:** "מצא יריב" פותח את מסך האימות עם ההודעה "כדי לשחק במדורג צריך לאמת את כתובת המייל."
   - חשבון חדש מתחיל ב־1200 "זמני" בכל סוג משחק: מהיר, רגיל וקשה.

## דברים לדעת

- **משחק מדורג אחד בכל פעם:** חשבון שמחפש, או שהמשחק המדורג שלו עוד לא נגמר, מקבל "כבר יש לך חיפוש או משחק מדורג פעיל, אולי במכשיר אחר.", עם קוד `alreadyQueued`.
  - **ב־3–4 שחקנים:** מי שנכנע לא יכול לחפש משחק חדש עד שהמשחק הקודם נגמר, כי הדירוג נכתב בסוף.
  - **נקודה פתוחה:** האם זה בסדר, או שצריך לשחרר אותו מיד אחרי הכניעה?
- **נטישה:** מי שיוצא אחרי "נמצא יריב!" נוטש. אחרי ה־grace (15 שניות) הוא מפסיד, והדירוג משתנה לפי הגנות היציאה (D32, אפיון 11.2): מי שיצא לפני הצעד הראשון שלו, או כשאף אחד לא הוביל עליו ברגע הניתוק, לא מפסיד דירוג. המשחק נספר בכל מקרה.
- **שרת שהופעל מחדש באמצע משחק:** המשחק אובד ונסגר בלי דירוג. זה מתועד ב־README, בסעיף Matchmaking.
- **אפשרות A (רשות):** ‏`RATING_OPTION=A` ב־`apps/server/.env`, ואז מפעילים מחדש את השרת.
  לכל סוג משחק ומספר שחקנים יש דירוג נפרד: בכרטיס "מדורג · 4" מופיע הדירוג של `fast-4p`. השרת עצמו נבדק בזה ב־`ranked.e2e.test.ts`.
